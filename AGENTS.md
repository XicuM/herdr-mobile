# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A phone companion for [Herdr](https://herdr.dev) (a terminal multiplexer for AI coding agents): a Flutter app, at the repo root (Android only; no `ios/` dir, and `linux/` is only the stock desktop runner), terminal-first on `xterm` 4.x. It talks over HTTP/WebSocket on port 7788 to [herdr-bridge](https://github.com/XicuM/herdr-bridge), which lives in its own repository (it was `bridge/` here, and the app `app/`, until the split): its routes and messages are in that repo's `PROTOCOL.md` and its internals in its `AGENTS.md`. Change the bridge there, additively, since this app and others depend on it. Every machine needs herdr 0.9.2 or later (written against 0.9.5).

Security, app side: every request but `/health` carries `Authorization: Bearer <token>`. The app keeps each bridge's token (pref `herdr_machine_tokens`, `machine=token`), entered in the machine dialog, and sends it to that bridge and the machines it reaches (`headersOf`); a refused connection is told from a bridge that's down by `GET /api/auth`, which answers 401 or 200. The bridge refuses any request carrying an `Origin` header, since browsers let any web page open a WebSocket to any address; the app's Dart client sends none. It also refuses a `Host` that is a dotted name other than `*.ts.net` (DNS rebinding), so machines must be added by IP, bare name or MagicDNS name. The APK keeps no Android backups (`allowBackup=false`).

## Commands

Mobile (run from the repo root):
```bash
flutter pub get
flutter run
flutter test                                  # test/widget_test.dart: model parsing, client state, widget tests
flutter test test/widget_test.dart --plain-name "SessionSnapshot parses correctly from JSON"
flutter analyze                               # flutter_lints via analysis_options.yaml
flutter build apk --release
```
CI (`.github/workflows/build-apk.yml`) runs on every push to main, on `v*` tags and by hand: `flutter build apk --release` on Flutter 3.24.x / JDK 17. It also builds the Linux desktop app on both runners (Flutter 3.47.6 cloned from git, since there's no arm SDK archive; `linux/`'s runner needs a newer Flutter than the APK's 3.24) as `herdr-mobile-linux-{x86_64,aarch64}.tar.gz`. On a tag it attaches the APK and those tarballs to the GitHub release. No tests run. Keep Flutter/Gradle/AGP versions compatible with 3.24.x (a newer local Flutter flags `ReorderableListView.onReorder` as deprecated; its replacement isn't in 3.24). Recent commits were spent fixing CI build breakage.

## Architecture

- Herdr payload shapes are handled loosely: code accepts both `snapshot.snapshot` and a bare snapshot, and alternate field names (`terminal_title_stripped`/`terminal_title`, `status`/`agent_status`). Keep that tolerance unless you've confirmed the real schema.
- The app relies on these bridge behaviours (see `PROTOCOL.md`): `WS /ws/session` sends `{"type":"snapshot","data":…}` on connect and whenever it changed, or `{"type":"error","error":…}` when there is none (and may send other types, which the app ignores); `WS /ws/term/{id}?cols&rows` is a terminal stream of herdr's *rendered viewport* (clear screen plus absolute cursor moves, no newlines), so history lives in herdr and is reached with `terminal.scroll`; while another client holds a pane the bridge sends `{"type":"term-closed","reason":…}` and the app offers a Take over button (`?takeover=1`).

**Mobile** (`lib/`):
- State lives in `HerdrClientService` (a `ChangeNotifier` created in `main.dart` and passed down through constructors).
- A machine is `host:port`, a bridge, or `host:port/m/<id>`, a machine that bridge reaches (`HerdrClientService.parentOf`); URLs are `http://$machine$path`. When a bridge connects, `_discover` fetches its `/api/machines` and puts them right after it, named as in herdr, and forgets those it no longer lists; a bridge's switch, removal and address change take them along. They can be renamed and switched off, and removing one removes it from that herdr. `errorOf(m)` is why a machine can't be shown: while disconnected, why its last connection failed (`_diagnose`: it asks `/api/auth` over HTTP and words the status or network error, e.g. a wrong token, a refused port, a name that doesn't resolve, a timeout); once connected, the bridge's `error` message. It shows in the machines' panel and in place of the terminal, and goes to `debugPrint` too.
- `HerdrClientService` keeps one `/ws/session` socket per saved machine (`_Conn`: socket, retry timer, last snapshot, selected pane), so several machines are connected at once. It applies each pushed snapshot (older bridges also send raw `event`s, which it ignores); a dropped socket retries after 3 s, doubling with each failure in a row up to ~3 min (reset by connecting, and on resume), so an unreachable machine doesn't keep the phone awake. Its pings, which notice a silently dead socket, come every 20 s on screen and every 90 s off it (`_ping`, set on the `dart:io` socket kept in `_Conn.socket`), since each wakes the radio. `_sync` (run from `notifyListeners`, after `start()`) opens a socket for every machine not in `_off`, the set the user disconnected (pref `herdr_machines_off`); `connect(m)`/`disconnect(m)` toggle one machine. The *active* machine (prefs `herdr_host`/`herdr_port`/`herdr_path`) is only the one on screen: `snapshot`, `selectedPaneId` and the bridge requests are its; `switchMachine` shows another without touching the rest. Saved machines are in `herdr_machines`, names in `herdr_machine_names` (`machine=name`). The machines' panel (the home screen's `endDrawer`, `MachineList` in `machines.dart`, opened by the computer icon on the top bar's right, green while one is connected) lists each with a green dot while connected or a warning on error (the error is in its page) and a switch; the + by its title adds a bridge or, through a bridge, an SSH machine saved in its herdr, and tapping one opens its page (`showMachinePage`, a full-screen dialog route: a status card with the whole error and its switch, then Connection (its address and token, one field grouping it as `K3MF-9QXA` and hiding a saved one, or SSH target; Address also takes a pairing link `herdrmobile://pair?to=host:port&token=…&name=…`, from herdr-bridge's `install.sh --phone`, pasted or scanned by its scan button (`MachineScreen._pair`; `scan` on the `herdr/android` channel is Play services' code scanner, so no camera permission)) and Display (its name), the machines a bridge reaches, and Remove); held and lifted (or right-clicked) it moves up or down, held and dragged it moves anywhere (`moveMachine`, the app's own order: a bridge with the machines it reaches, those among themselves under it); a reached one's name and SSH target are edited, and it is removed, in that herdr. Bridge requests all go through `_request` (to the active machine, or the one passed as `on`; then refetch the snapshot over HTTP); failures go to the `onError` callback, which `HerdrMobileApp` shows as a SnackBar on any screen.
- `PtyChannel` holds one `/ws/term/{id}` socket for the selected pane and writes incoming bytes straight into the single xterm `Terminal`. It switches xterm to the alt screen (no local scrollback) and clears it in front of every (re)connect's first frame, because herdr repaints the pane on attach; `onAttach` then scrolls back to where the screen was in that pane's history (`_scrolledUp` scrolls carrying `_scrolledLines`), so a lost connection keeps the place; another pane returns to where it was left (`_places`, static, by `machine/pane`), unless its agent's `state_change_seq` moved since, which starts it live, since the replay counts from the bottom and lands on other text once the pane has printed. One-finger drags on the terminal send `terminal.scroll` (`TerminalScreen._scroll`); xterm's own `simulateScroll` is off. A tap on the terminal (or a left click) is a click for the pane's program (`_onTap` → `PtyChannel.sendClick`, `{"type":"terminal.mouse","action":"down"|"up","button":"left","column","row"}`, 0-based), which herdr encodes in the mode the program asked for and drops when it asked for none. Herdr never tells the client that mode, so a finger's tap is only that click, never the control keys nor the soft keyboard: the keys come only from their button, and the keyboard only from the keyboard button beside them. The keyboard never opens on touch (`_gateKeyboard` holds off xterm's own tap-down by `canRequestFocus` on its focus node, which only the keyboard button puts back), so a tap, a long-press to select or a scroll never shrinks the pane and makes herdr redraw it under the selection; on Android the terminal doesn't autofocus, which would open it with every agent. A tap that clears a selection does only that, and the word xterm selects on a double-tap is cleared. While text is selected the pane holds still (`PtyChannel.hold` keeps herdr's frames until it's cleared), and it has a text field's two handles to adjust it (`_handleAt`/`_dragHandle`); input, scrolling or another pane let go of it. Ctrl+C copies that selection, as VS Code's does. Omarchy's Super+C reaches the pane as a Ctrl+C whose Control key event the desktop synthesized (`KeyEvent.synthesized`, since no Control key was pressed), and that is what keeps a copy gesture from interrupting the pane: with nothing selected it does nothing, while a real Ctrl+C, with its own Control key, stays xterm's interrupt (`_onTermKeyEvent`). Android 13+ confirms copies itself, so "Copied" shows only below it (`systemShowsCopies`, from the MethodChannel's `sdk`). Two fingers swiped sideways (or a touchpad's two-finger pan, sideways; up/down scrolls) show the next or previous agent (`stepAgent`/`agentAt`: agents in the order shown on the agents page, wrapping), the terminal following the fingers with where each way leads peeking behind it, switching only when they lift past 80dp (a tick marks the point); fingers spreading first pinch-zoom instead. Swiping down with two fingers together closes the current tab, undoable like its menu's Close tab, and never with text selected. The screen counts lines scrolled back (`_scrolledUp`) to show a centred ↓ button that returns to live, and any input scrolls back to live first. `TerminalScreen` rebuilds the channel whenever `selectedPaneId` or the machine changes, and drops it while the app is in the background so the takeover ends.
- **Background alerts** (Android side in `android/.../HerdrApp.kt`): `HerdrApp` (the `Application`) owns the Flutter engine, so Dart, and with it `HerdrClientService`, outlives `MainActivity`. While alerts are on (pref `background_alerts`), Dart drives `StatusService`, a foreground service whose ongoing notification shows the connection state, over the `herdr/android` MethodChannel (`status`, `alert`, `cancel`, `askPermissions`; native calls back `open` when an alert is tapped, and `disconnect` from the notification's Disconnect action, which turns every machine off). The `HerdrClientService.notifyListeners` override pushes the status on every change. `_alertChanges` diffs consecutive snapshots: a pane entering `blocked` raises "Claude needs you", and an agent's `completion_seq` rising past the highest seen for that pane (`_Conn.completions`, since an HTTP-fetched snapshot can land after a newer pushed one) raises "Claude finished" (never a mere working → idle, which an interrupt also is); the text is the agent's summary, the header its place and machine, and its logo the large icon, the only one a collapsed notification shows. The ongoing notification's title is the most urgent count across machines ("2 agents need you"), its text a line per machine with `monitoring` counted apart from `idle`, as the list shows it. Don't key completion on `done`: herdr only shows `done` until the pane is viewed, so a visible pane goes straight from `working` to `idle`. There are no Flutter plugins for this; the Kotlin is plain platform APIs.
- **Files from agents** (`herdr-bridge send`): the bridge pushes `{"type":"delivery",…}` on `/ws/session`, only to the app on another device than the bridge's (see its `PROTOCOL.md`). `_delivered` keeps it as a `Delivery` in `HerdrClientService._deliveries` (in memory; dropped with its pane) and, unless that pane is on screen or muted or alerts are off, alerts through the same `alert` call with `delivery` and `action` ("Install" for an APK, else "Open"), which Kotlin posts on the `files` channel with that button; the button opens the activity with the delivery's id, which Dart opens. `deliveriesOf(m, pane)` (that pane's, plus those with no `pane_id`, sent from another herdr session) are cards above the message box in `TerminalScreen` (`_deliveryCard`: the newest, the rest behind "N more"), and the newest leads that agent's row in the list. `openDelivery` downloads `GET /api/deliveries/{id}` once (progress on `Delivery.progress`): on Android to the cache's `deliveries/` (`deliveriesDir`, keeping only files still offered) and opens it through `openFile`, an `ACTION_VIEW` on a `FileProvider` URI (`res/xml/deliveries.xml`; an APK opens the installer, hence `REQUEST_INSTALL_PACKAGES`); on Linux to the Downloads folder, then `xdg-open`.
- All input goes over the pane WS. Terminal keystrokes and the control keys go through `TerminalScreen._send`, which applies an armed CTRL once; special keys use `Terminal.keyInput` so they follow cursor-key mode. There are two places to type: the message box, or the terminal itself with the control keys (`KeyboardAccessoryBar`, a row that scrolls sideways once its keys would be narrower than 48dp) in the box's place (pref `show_keys`, default off). The control keys' button, on the left of the box, brings the keys without the keyboard. On the right, the box's send button; beside the keys, the message box button on the left goes back to the box and the keyboard button on the right shows or hides the keyboard; a keyboard that is up stays up across the swap. The history button inside the box, on its left, opens sent messages and recent slash commands; the image button inside the box, on its right, picks a picture, uploads it to the active machine's bridge (`POST /api/uploads`) and puts its `@`-reference in the box to review and send. The agent's usage (quota %) is on the top bar, left of the machine chip. The message box (`_sendMessage`) sends its text as one bracketed paste (when the pane has enabled it) plus Enter; an empty box sends just Enter. Each pane keeps its own unsent draft (`_drafts`, in memory and static so it outlives the screen, by `machine/pane`); sent messages are kept, for all panes alike, in pref `message_history` and offered by that history button; a history entry goes in the box to edit, while a recent slash command sends straight away (not kept in history). On Android the volume keys, while the terminal screen is on top, change the font size, send ↑/↓, or are left to the system (`VolumeKeys`, pref `volume_keys`, set in Settings; `_onHardwareKey`); Ctrl + and Ctrl - (and Ctrl 0 to reset) zoom the terminal font on Linux/desktop.
- It is laid out like WhatsApp: a list of agents leading into each one's terminal, like chats. The home screen (`AgentsHomeScreen`, `agents_home_screen.dart`) lists every agent on every connected machine as a plain M3 list with faint full-width hairlines between rows, most urgent first and then most recently changed. Each row, like the terminal's top bar, is titled by the summary the agent's terminal title gives (`titleMedium`, bold while it needs you; the agent's name when empty), and under it, smaller, where it is: `SessionSnapshot.placeOf` (the workspace's name, a worktree's being its branch, then `(tab_name)` when the workspace has several tabs), then the machine (with more than one), separated by ` · `. It has the agent's logo (`AgentAvatar`, logos in `assets/logos/`) and on the right when it last changed status, a muted icon and its status text/dot. herdr sends no timestamps, so that time is when the app saw `state_change_seq` rise (`changedAt`); those times are kept across restarts (pref `agent_changes`) and taken back while the agent's `state_change_seq` is still the saved one; other agents already there in a machine's first snapshot have none, and sort after, by `state_change_seq` (one counter for all of herdr's panes; viewing a `done` pane doesn't bump it, so it isn't a change). With no machine connected the search bar's hint says "Connecting…". Tapping an agent switches machine and pushes `TerminalScreen`. There is no FAB: agents start in herdr, and in the workspaces drawer each machine's name has a + that opens a new workspace there and its terminal. Swiping right reveals Mute/Unmute, left reveals Close (a slide-and-press action drawer; pressing the revealed button executes the action; tapping the tile or scrolling closes it; DELETE /api/pane/{id} → pane.close without a snackbar). herdr closes a workspace with its last pane, so `closePane` first opens a tab in a workspace that has no other. Long-pressing one, or tapping its avatar, selects it as in Gmail: taps then select more, back clears, and the top bar's actions select all, mute (or unmute, when all are) and close the selection. `closePane` takes the agent's machine, so closing never switches the screen. The top bar has ☰ on its left, a search pill in the middle (a stadium `Container` with the search icon in a 48dp slot on its left, as wide a slot on its right for the clear button, and a `TextField` centred between; M3's `SearchBar` can't centre its text), and on its right the machines' icon (green while one is connected). ☰ opens the drawer and tapping the machines icon opens the machines' panel (only they do, `drawerEnableOpenDragGesture`/`endDrawerEnableOpenDragGesture: false`, since an edge swipe would fight the rows' swipe and Android's back). The drawer (`WorkspacesDrawer`, shared with the terminal's) holds Settings at its foot and the workspaces (`WorkspaceList` in `workspaces.dart`, modelled on Herdr's sidebar: each connected machine's workspaces under its name (always shown, with its +; one off, connecting or failing is left out), linked worktrees nested; tap one to open its terminal, hold it and lift (or right-click) for its menu (`showWorkspaceContextMenu`, below), hold and drag to reorder it, worktrees included, via `POST /api/workspace/move` → `workspace.move_block`, herdr's own order so the desktop follows; each acts on its row's machine first, since requests go to the active one; opening a terminal from it closes it first). There is no bottom bar, so no unread badge: the agents that need you are on top and in bold. Tapping the search bar (`_query` non-null) swaps ☰ for back and replaces the body with sectioned results, as WhatsApp's: Agents (the list's own rows, swipes and selection included), Workspaces (worktrees too), Tabs (how a plain shell is found by name) and Machines (`MachineList(only:)`). Every word must be somewhere in what a result shows or is known by: names, branch, the worktree's repository, its agents, its machine, its status's label or `machineStatus`. Tapping a result switches to its machine and opens its terminal (a machine opens its page); search stays open behind it, and back closes it after any selection. The welcome and "What's new" dialog shows from the home screen.
- On a landscape tablet (`_isWide`: at least 840dp wide and 600dp on its short side, so not a phone in landscape) the home screen is M3's list-detail layout: the list and its top bar in a 360dp pane on the left, and the selected pane's terminal beside it (`TerminalScreen(embedded: true)`: no back button, and it never pops itself; the home screen shows "No agent open" instead once its pane or machine is gone). Tapping an agent shows it there instead of pushing, and its row is marked. Turning narrow pushes the shown terminal, and turning wide pops a pushed one back beside the list (`_onWidthChange`).
- `TerminalScreen` is the chat: back returns to the list, and if its machine is switched off or removed it pops itself, with whatever is open over it. A pane herdr couldn't restore after a restart (`restore_error`: its folder is gone, its shell won't start) has no terminal, so it shows that reason in the terminal's place, as herdr's own window does, and isn't attached. Its top bar shows the workspace: its name (a linked worktree's with a "worktree" tag) and under it the branch. On the right, the agent's usage (its logo and the quota left in done's green, from 75% used the draft peach, from 90% needs-you's red, and grey with nothing recorded; none for a pane with no agent), which opens its usage sheet, and an `ActionChip` with the machine's name and its status (`machineStatusIcon`, drawn the same everywhere: green dot connected, hollow dot connecting, warning on error, none when off), which opens its page (`showMachinePage`: its status with the whole error, its switch, then Connection, Display, Remove); the header names the workspace (its branch and ↑↓ counts with it) and opens the workspaces panel when tapped: the home screen's beside the list, else the terminal's own over it, where picking one switches the pane in place. Its actions are in that panel. Alt+W closes the pane and goes back. Under the top bar, in `AppBar.bottom`, the workspace's tabs, like Vivaldi's: a strip of equal 168dp tabs that scrolls when they overflow, kept scrolled to the current one; it's how plain shells are reached, since the list shows only agents. Each tab shows its agent's avatar with an online status ring and its truncated summary (`_tabSummary`); the current tab is rounded on top and takes the terminal's background, joined to it, against the bar's `surfaceContainer`; a fixed new-tab button at the end; a tab held and lifted (or right-clicked) has a menu to open it (or, when it's open, clear it), move it left or right or close it; hold and drag a tab to move it, the others sliding aside to show where it lands (a horizontal `ReorderableListView`; `POST /api/tab/move` → `tab.move`, whose `insert_index` counts in the order before the move). It is the one hand-drawn control besides the terminal, since M3 has no browser tab. The UI is Material 3: the theme in `main.dart` is `ColorScheme.fromSeed` in light and dark, from the accent colour and light/dark/system mode picked in Settings (`HerdrClientService.seed`/`brightness`, prefs `theme_seed`/`theme_mode`; with no accent picked it follows Material You's, read from Android 12+ over the MethodChannel's `systemColor` on every resume, else sky), widgets use scheme roles, the type scale and stock M3 components; only the terminal uses the Meslo font, and only `AgentStatus.color` (with which the usage chip also warns) and the connected green are hardcoded.
- A workspace's menu is Herdr's own sidebar's (herdr v0.9.5 `src/client/shell/context_menu.rs`): Rename and Close; **Close group** instead for a repository's main workspace while its linked worktrees are open (herdr refuses to close it alone, `workspace_group_close_required`, so it sends `close_group`); New worktree (a branch, checked out if it exists, else made from the main checkout's HEAD) and Open worktree… (`worktree.list`'s linked, openable checkouts) on a git workspace that isn't a linked worktree (herdr refuses those from one, `linked_worktree_source`); and, only on a linked worktree, Delete worktree checkout (`worktree.remove`: `git worktree remove`, which closes its workspace and keeps its branch; it is asked about first, in one "Delete <label>?" dialog that warns anything uncommitted is lost and so sends `force`, since herdr's `dirty_worktree_requires_force` refusal is its only sign of a dirty checkout). Closing never touches a checkout. A workspace is named by herdr's label as it is (`WorkspaceModel.displayName`), a linked worktree's too: guessing a rename from the branch lost names that matched the checkout folder. Its branch follows with ↑ commits to push and ↓ to pull (`aheadBehind`, from the bridge's `git_ahead`/`git_behind`), and a workspace's worktrees can be hidden under it (`WorkspaceList.collapsed`). Holding means the same everywhere but on agent rows (where it selects, as in Gmail): as with a launcher's icons, a workspace, machine or tab held still and lifted shows its menu, and held and dragged moves it (`HoldMenu` in `workspaces.dart`, which also takes the right-click; no ⋮ buttons).
- Closing a tab or workspace is never asked about but always undoable: a tab (swipe, menu, Alt+W) or a workspace hides at once and a SnackBar ("Tab closed", "Workspace closed") offers Undo just above the message bar (or at the bottom), as Gmail's does, in M3's inverse surface colours; the request goes once it ends without Undo, or another replaces it (`closeWithUndo` in `workspaces.dart`, over `HerdrClientService.closeUnlessUndone`, which keeps herdr's snapshot as `_Conn.raw` and shows it less `_hidden`; a hidden selected pane moves on as when herdr closes it). Agents closed from the list use slide-and-press confirmation and close directly without a snackbar. Deleting a worktree checkout is instead never undoable, so it is asked about first — its one dialog warns that uncommitted work goes with it — and removing a machine is the other thing asked about first.
- `lib/changelog.dart` (newest first) drives the first-launch welcome and the one-time "What's new" dialog, keyed by the `last_seen_changelog` pref. When releasing, bump the version in `pubspec.yaml` (Gradle reads it), then add a changelog entry.
- `models/session.dart` mirrors the Herdr snapshot schema (`workspaces`/`tabs`/`panes`/`agents`, snake_case ids like `w1:p1`). Agent statuses are `working | blocked | done | idle | unknown` (`AgentStatus`, an enum with each one's colour). In text, `blocked` is "needs you" (alerts, the machine summary).
