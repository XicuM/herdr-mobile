# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A phone companion for [Herdr](https://herdr.dev) (a terminal multiplexer for AI coding agents). It has two parts that talk over HTTP/WebSocket on port 7788, and the bridge is meant to bind to the host's Tailscale IP. Tailscale decides who can reach it, and a token decides who may use it: every request but `/health` carries `Authorization: Bearer <token>` (`require_token`; `bridge/src/token.rs` makes it on first start in `~/.config/herdr-bridge/token`, mode 0600, and refuses one others can read; `herdr-bridge --print-token` prints it; 8 characters like `K3MF-9QXA`, matched ignoring case, spaces and dashes). A wrong token is answered after a second, one at a time however many arrive (`REFUSALS`), which is what keeps 8 characters from being guessed. Without it, other users on the bridge's machine or on the tailnet could type into every pane. The app keeps each bridge's token (pref `herdr_machine_tokens`, `machine=token`), entered in the machine dialog, and sends it to that bridge and the machines it reaches (`headersOf`); a refused connection is told from a bridge that's down by `GET /api/auth`, which answers 401 or 200. The checks run before `pick_machine`, so a refused request never connects to a remote machine. The bridge refuses any request carrying an `Origin` header (`reject_browsers`), since browsers let any web page open a WebSocket to any address and the app's Dart client sends none. It also refuses a `Host` that is a dotted name other than `*.ts.net` (DNS rebinding: a same-origin GET carries no `Origin`), so machines must be added by IP, bare name or MagicDNS name. The APK keeps no Android backups (`allowBackup=false`).

- `bridge/`: Rust daemon (axum + tokio). It translates between Herdr's Unix-socket JSON-RPC (`~/.config/herdr/herdr.sock`) and HTTP/WS. It also serves the machines saved in that herdr (`herdr machine list`) over SSH, so they need neither Tailscale nor a bridge of their own.
- `app/`: Flutter app (Android only; no `ios/` dir, and `linux/` is only the stock desktop runner). It's a terminal-first UI on `xterm` 4.x.

## Commands

Bridge (run from `bridge/`):
```bash
cargo build --release
cargo run -- --port 7788        # the default bind is 0.0.0.0; flags also read from env: HERDR_SOCKET, HERDR_BRIDGE_BIND, HERDR_BRIDGE_PORT
RUST_LOG=herdr_bridge=debug cargo run
../deploy/start-bridge.sh        # binds 0.0.0.0 (or HERDR_BRIDGE_BIND); runs ~/.local/bin, target/release, target/debug or PATH
```
`cargo test` runs the bridge's few unit tests (`usage.rs`, `token.rs`). `deploy/install.sh` installs the binary and `start-bridge.sh` to `~/.local/bin` and sets up `herdr-bridge.service` (systemd user unit, which sets its own `PATH` so `herdr`, `git` and `tailscale` resolve) or `dev.herdr.bridge.plist` (launchd, logging to `~/Library/Logs/herdr-bridge.log`).

Mobile (run from `app/`):
```bash
flutter pub get
flutter run
flutter test                                  # test/widget_test.dart: model parsing, client state, widget tests
flutter test test/widget_test.dart --plain-name "SessionSnapshot parses correctly from JSON"
flutter analyze                               # flutter_lints via analysis_options.yaml
flutter build apk --release
```
CI (`.github/workflows/build-apk.yml`) runs on every push to main, on `v*` tags and by hand: `flutter build apk --release` on Flutter 3.24.x / JDK 17, plus `cargo build --release` for the bridge on native ubuntu-22.04 x86_64 and arm runners. On a tag it attaches the APK and `herdr-bridge-linux-{x86_64,aarch64}` to the GitHub release. No tests run. Keep Flutter/Gradle/AGP versions compatible with 3.24.x (a newer local Flutter flags `ReorderableListView.onReorder` as deprecated; its replacement isn't in 3.24). Recent commits were spent fixing CI build breakage.

## Architecture

**Bridge data flow** (`bridge/src/`):
- `herdr.rs` `HerdrClient`: each `call()` opens a new Unix socket connection (`send`), or for a remote machine (`HerdrClient::remote`) runs `ssh <target> herdr remote-api-bridge` (herdr's hidden stdio pipe to that machine's socket, as `herdr --machine` uses; with `--session` for a machine saved with another session; herdr's own commands there get it too), writes one newline-delimited JSON request `{id, method, params}`, and reads one response line, failing after 10 s. `snapshot()` wraps `session.snapshot`, drops what the app doesn't read and would push it a snapshot every second or two (`layouts`, whose scroll offsets move, and the raw `terminal_title` wherever a `terminal_title_stripped` exists, since Claude Code's spinner turns in it), adds each agent's `usage` on this machine only (`usage.rs`, from the agents' own transcripts and usage files, read on a blocking thread and cached 30 s; never credentials, and no made-up limits), and adds each workspace's `git_branch` (one `sh` running `git branch --show-current` in each directory; left out when empty). `command()` runs a program on the machine: locally, or over SSH with every argument quoted and `~/.local/bin` on `PATH`, sharing one SSH connection (`ControlMaster`, `BatchMode`, so the key must work without a prompt; its socket goes in `XDG_RUNTIME_DIR`, else `~/.ssh`, never a shared `/tmp`, where another user could plant one). Server routes pass most calls straight through via `server.rs` `rpc`; POST routes whose body is herdr's params are `pass("method")`. A separate long-lived connection runs `events.subscribe` and fans the events out through a `tokio::broadcast` channel. It reconnects forever, backing off to once a minute while it fails.
- `server.rs` routes, for this machine at `/` and for each machine saved in herdr at `/m/<id>/` (`pick_machine` cuts the prefix before routing and hands the routes that machine's `AppState` as an `Extension`; a remote's event listener and poller start on its first request):
  - `GET /health`, `GET /api/snapshot`, `GET /api/machines` (the saved machines: `id`, `label`, `target`), `POST /api/machines` `{target, label}` → `herdr machine add`, `POST /api/machines/{id}` `{target, label}` → `herdr machine rename`, and for another target `machine add` (same session) then `machine remove`, since herdr can't change a target (the machine gets a new id), `DELETE /api/machines/{id}` → `herdr machine remove`
  - `POST /api/tab`, `DELETE /api/tab/{id}`, `POST /api/tab/{id}/rename`, `POST /api/tab/move` → `tab.move`, `POST /api/workspace` (plus workspace delete/rename, `POST /api/workspace/move` → `workspace.move_block`, and worktree routes)
  - `WS /ws/session`: sends the snapshot as `{"type":"snapshot","data":…}` on connect (fetched for that phone) and then whenever it changed; with no snapshot it sends `{"type":"error","error":…}` instead (herdr down; for a remote, herdr's own reason from `herdr --machine <id> api snapshot`, e.g. "update Herdr on this machine", else just "Error"). One shared poller (`start_snapshot_poller`, a `watch` channel in `AppState`) serves every phone and runs only while one is connected: right after any Herdr event (a burst makes one snapshot), and every 1.5 s. The poll is needed because herdr's global `events.subscribe` carries no agent status changes (`pane.agent_status_changed` requires a `pane_id`).
  - `WS /ws/term/{id}?cols&rows`: a real terminal stream. It first calls `pane.focus`, the only thing that marks a pane seen in herdr (`done` turns `idle`; the takeover alone doesn't), so the desktop follows the phone. Then it spawns `herdr terminal session control <pane> --takeover` and relays its base64 frames as binary WS frames. Binary frames in are terminal input. A text frame with a `type` (e.g. `{"type":"terminal.scroll","direction":"up"|"down","lines":N}`) goes to herdr as-is; one without is a resize `{"cols","rows"}`. The frames out are herdr's *rendered viewport* (clear screen plus absolute cursor moves, no newlines), so the client never accumulates scrollback: history lives in herdr and is reached with `terminal.scroll`. On close it sends `terminal.release` so the desktop gets its size back. When herdr can't start or ends the session (`terminal.closed`'s `reason`, or its stderr), that text goes to the terminal as a frame. A pane id starting with `-` is refused, since herdr's parser has no `--`.
- Herdr payload shapes are handled loosely: code accepts both `snapshot.snapshot` and a bare snapshot, and alternate field names (`terminal_title_stripped`/`terminal_title`, `status`/`agent_status`). Keep that tolerance unless you've confirmed the real schema.

**Mobile** (`app/lib/`):
- State lives in `HerdrClientService` (a `ChangeNotifier` created in `main.dart` and passed down through constructors).
- A machine is `host:port`, a bridge, or `host:port/m/<id>`, a machine that bridge reaches (`HerdrClientService.parentOf`); URLs are `http://$machine$path`. When a bridge connects, `_discover` fetches its `/api/machines` and puts them right after it, named as in herdr, and forgets those it no longer lists; a bridge's switch, removal and address change take them along. They can be renamed and switched off, and removing one removes it from that herdr. The bridge's `error` message is `errorOf(m)`, shown in the machines' panel and in place of the terminal.
- `HerdrClientService` keeps one `/ws/session` socket per saved machine (`_Conn`: socket, retry timer, last snapshot, selected pane), so several machines are connected at once. It applies each pushed snapshot (older bridges also send raw `event`s, which it ignores); a dropped socket retries after 3 s, doubling with each failure in a row up to ~3 min (reset by connecting, and on resume), so an unreachable machine doesn't keep the phone awake. Its pings, which notice a silently dead socket, come every 20 s on screen and every 90 s off it (`_ping`, set on the `dart:io` socket kept in `_Conn.socket`), since each wakes the radio. `_sync` (run from `notifyListeners`, after `start()`) opens a socket for every machine not in `_off`, the set the user disconnected (pref `herdr_machines_off`); `connect(m)`/`disconnect(m)` toggle one machine. The *active* machine (prefs `herdr_host`/`herdr_port`/`herdr_path`) is only the one on screen: `snapshot`, `selectedPaneId` and the bridge requests are its; `switchMachine` shows another without touching the rest. Saved machines are in `herdr_machines`, names in `herdr_machine_names` (`machine=name`). The machines' panel (the home screen's `endDrawer`, `MachineList` in `machines.dart`, opened by the computer icon on the top bar's right, green while one is connected) lists each with a green dot while connected or a warning on error (the error is in its dialog) and a switch; the + by its title adds a bridge or, through a bridge, an SSH machine saved in its herdr, and tapping one edits or removes it; its ⋮ moves it up or down and a long-press drags it (`moveMachine`, the app's own order: a bridge with the machines it reaches, those among themselves under it); a reached one's name and SSH target are edited, and it is removed, in that herdr (`showMachineDialog`). Bridge requests all go through `_request` (to the active machine, or the one passed as `on`; then refetch the snapshot over HTTP); failures go to the `onError` callback, which `HerdrMobileApp` shows as a SnackBar on any screen.
- `PtyChannel` holds one `/ws/term/{id}` socket for the selected pane and writes incoming bytes straight into the single xterm `Terminal`. It switches xterm to the alt screen (no local scrollback) and clears it in front of every (re)connect's first frame, because herdr repaints the pane on attach; `onAttach` then resets the screen's scroll count. One-finger drags on the terminal send `terminal.scroll` (`TerminalScreen._scroll`); xterm's own `simulateScroll` is off. The soft keyboard opens when a tap on the terminal lifts (`_gateKeyboard`, which holds off xterm's own tap-down by `canRequestFocus` on its focus node), so a long-press to select or a scroll never shrinks the pane and makes herdr redraw it under the selection; on Android the terminal doesn't autofocus, which would open it with every agent. It waits out a double-tap (whose second tap selects a word), and with the message box focused a tap on the terminal puts the keyboard away instead. While text is selected the pane holds still (`PtyChannel.hold` keeps herdr's frames until it's cleared), and it has a text field's two handles to adjust it (`_handleAt`/`_dragHandle`); input, scrolling or another pane let go of it. Android 13+ confirms copies itself, so "Copied" shows only below it (`systemShowsCopies`, from the MethodChannel's `sdk`). Two fingers swiped sideways (or a touchpad's two-finger pan, sideways; up/down scrolls) show the next or previous agent (`stepAgent`/`agentAt`: connected machines in their order, then herdr's workspaces, tabs and panes, wrapping), the terminal following the fingers with where each way leads peeking behind it, switching only when they lift past 80dp (a tick marks the point); fingers spreading first pinch-zoom instead. The screen counts lines scrolled back (`_scrolledUp`) to show a centred ↓ button that returns to live, and any input scrolls back to live first. `TerminalScreen` rebuilds the channel whenever `selectedPaneId` or the machine changes, and drops it while the app is in the background so the takeover ends.
- **Background alerts** (Android side in `android/.../HerdrApp.kt`): `HerdrApp` (the `Application`) owns the Flutter engine, so Dart, and with it `HerdrClientService`, outlives `MainActivity`. While alerts are on (pref `background_alerts`), Dart drives `StatusService`, a foreground service whose ongoing notification shows the connection state, over the `herdr/android` MethodChannel (`status`, `alert`, `cancel`, `askPermissions`; native calls back `open` when an alert is tapped, and `disconnect` from the notification's Disconnect action, which turns every machine off). The `HerdrClientService.notifyListeners` override pushes the status on every change. `_alertChanges` diffs consecutive snapshots: a pane entering `blocked` raises "Needs you", and an agent's `completion_seq` rising past the highest seen for that pane (`_Conn.completions`, since an HTTP-fetched snapshot can land after a newer pushed one) raises "Finished". Don't key completion on `done`: herdr only shows `done` until the pane is viewed, so a visible pane goes straight from `working` to `idle`. There are no Flutter plugins for this; the Kotlin is plain platform APIs.
- All input goes over the pane WS. Terminal keystrokes and the control keys go through `TerminalScreen._send`, which applies an armed CTRL once; special keys use `Terminal.keyInput` so they follow cursor-key mode. The button left of the message bar swaps the message box for the control keys (`KeyboardAccessoryBar`) and back (pref `show_keys`, default off); a keyboard that is up stays up, typing into the terminal beside the keys. The history button inside the box, on its left, opens sent messages and quick replies; the agent's usage (⚡) is on the top bar, left of the machine chip. The message box (`_sendMessage`) sends its text as one bracketed paste (when the pane has enabled it) plus Enter; an empty box sends just Enter. Each pane keeps its own unsent draft (`_drafts`, in memory and static so it outlives the screen, by `machine/pane`); sent messages are kept, for all panes alike, in pref `message_history` and offered, with quick replies, by that history button; a history entry goes in the box to edit, a quick reply is sent straight away (not kept in history). The volume keys, while the terminal screen is on top, change the font size, send ↑/↓, or are left to the system (`VolumeKeys`, pref `volume_keys`, set in Settings; `_onHardwareKey`); Ctrl + and Ctrl - (and Ctrl 0 to reset) zoom the terminal font on Linux/desktop.
- It is laid out like WhatsApp: a list of agents leading into each one's terminal, like chats. The home screen (`AgentsHomeScreen`, `agents_home_screen.dart`) lists every agent on every connected machine as a plain M3 list with faint full-width hairlines between rows, most urgent first and then most recently changed. Each row, like the terminal's top bar, is titled by the summary the agent's terminal title gives (`titleMedium`, bold while it needs you; the agent's name when empty), and under it, smaller, where it is: `SessionSnapshot.placeOf` (the workspace's name, a worktree's being its branch, then `(tab_name)` when the workspace has several tabs), then the machine (with more than one), separated by ` · `. It has the agent's logo (`AgentAvatar`, logos in `assets/logos/`) and on the right when it last changed status, a muted icon and its status text/dot. herdr sends no timestamps, so that time is when the app saw `state_change_seq` rise (`changedAt`); agents already there in a machine's first snapshot have none, and sort after, by `state_change_seq` (one counter for all of herdr's panes; viewing a `done` pane doesn't bump it, so it isn't a change). With no machine connected the search bar's hint says "Connecting…". Tapping an agent switches machine and pushes `TerminalScreen`. There is no FAB: agents start in herdr, and in the workspaces drawer each machine's name has a + that opens a new workspace there and its terminal. Swiping right mutes it (no alerts; pref `muted_panes`, `host:port/pane_id`, dropped once the pane is gone since herdr reuses ids), left closes it: the row hides at once and `DELETE /api/pane/{id}` → `pane.close` goes once the "Agent closed" SnackBar ends without Undo (or another replaces it). herdr closes a workspace with its last pane, so `closePane` first opens a tab in a workspace that has no other. Long-pressing one, or tapping its avatar, selects it as in Gmail: taps then select more, back clears, and the top bar's actions select all, mute (or unmute, when all are) and close the selection (with the same Undo). `closePane` takes the agent's machine, so closing never switches the screen. The top bar has ☰ on its left, a search pill in the middle (a stadium `Container` with the search icon in a 48dp slot on its left, as wide a slot on its right for the clear button, and a `TextField` centred between; M3's `SearchBar` can't centre its text), and on its right the machines' icon (green while one is connected). ☰ opens the drawer and tapping the machines icon opens the machines' panel (only they do, `drawerEnableOpenDragGesture`/`endDrawerEnableOpenDragGesture: false`, since an edge swipe would fight the rows' swipe and Android's back). The drawer holds Settings at its foot and the workspaces (`WorkspaceList` in `workspaces.dart`, modelled on Herdr's sidebar: each connected machine's workspaces under its name (always shown, with its +; one off, connecting or failing is left out), linked worktrees nested; tap one to open its terminal, its ⋮ (or a right-click) for its actions and Move up/down, long-press and drag to reorder it, worktrees included, via `POST /api/workspace/move` → `workspace.move_block`, herdr's own order so the desktop follows; each acts on its row's machine first, since requests go to the active one; opening a terminal from it closes it first). There is no bottom bar, so no unread badge: the agents that need you are on top and in bold. Tapping the search bar (`_query` non-null) swaps ☰ for back and replaces the body with sectioned results, as WhatsApp's: Agents (the list's own rows, swipes and selection included), Workspaces (worktrees too), Tabs (how a plain shell is found by name) and Machines (`MachineList(only:)`). Every word must be somewhere in what a result shows or is known by: names, branch, the worktree's repository, its agents, its machine, its status's label or `machineStatus`. Tapping a result switches to its machine and opens its terminal (a machine opens its dialog); search stays open behind it, and back closes it after any selection. The welcome and "What's new" dialog shows from the home screen.
- On a landscape tablet (`_isWide`: at least 840dp wide and 600dp on its short side, so not a phone in landscape) the home screen is M3's list-detail layout: the list and its top bar in a 360dp pane on the left, and the selected pane's terminal beside it (`TerminalScreen(embedded: true)`: no back button, and it never pops itself; the home screen shows "No agent open" instead once its pane or machine is gone). Tapping an agent shows it there instead of pushing, and its row is marked. Turning narrow pushes the shown terminal, and turning wide pops a pushed one back beside the list (`_onWidthChange`).
- `TerminalScreen` is the chat: back returns to the list, and if its machine is switched off or removed it pops itself. Its top bar, like a chat's header, shows the agent as its row does: avatar, summary, and under them its place (branch); on the right, a chip with the machine's name and its connection status dot; tapping the header (on mobile) or right-clicking it (on Linux/desktop context menu, `showWorkspaceContextMenu`) opens the workspace's actions (`showWorkspaceActions` in `workspaces.dart`: rename, new worktree, open worktree, delete; delete runs without asking, like closing a tab, and from the terminal pops back to the list, while from the drawer or search a new or opened worktree opens its terminal). Its menu mutes, or closes the pane and goes back. Under the top bar, in `AppBar.bottom`, the workspace's tabs, like Vivaldi's: a strip of equal 168dp tabs that scrolls when they overflow, kept scrolled to the current one; it's how plain shells are reached, since the list shows only agents. Each tab shows its agent's avatar with an online status ring and its truncated summary (`_tabSummary`); the current tab is rounded on top and takes the terminal's background, joined to it, against the bar's `surfaceContainer`; a fixed new-tab button at the end; the current tab has a ⋮ (any tab, on a right-click) to move it left or right or close it; long-press and drag a tab onto another to take its place (`POST /api/tab/move` → `tab.move`, whose `insert_index` counts in the order before the move). It is the one hand-drawn control besides the terminal, since M3 has no browser tab. The UI is Material 3: the theme in `main.dart` is `ColorScheme.fromSeed` in light and dark, from the accent colour and light/dark/system mode picked in Settings (`HerdrClientService.seed`/`brightness`, prefs `theme_seed`/`theme_mode`; with no accent picked it follows Material You's, read from Android 12+ over the MethodChannel's `systemColor` on every resume, else sky), widgets use scheme roles, the type scale and stock M3 components; only the terminal uses the Meslo font, and only `AgentStatus.color` and the machines icon's connected green are hardcoded.
- `lib/changelog.dart` (newest first) drives the first-launch welcome and the one-time "What's new" dialog, keyed by the `last_seen_changelog` pref. When releasing, bump the version in `pubspec.yaml` (Gradle reads it), then add a changelog entry.
- `models/session.dart` mirrors the Herdr snapshot schema (`workspaces`/`tabs`/`panes`/`agents`, snake_case ids like `w1:p1`). Agent statuses are `working | blocked | done | idle | unknown` (`AgentStatus`, an enum with each one's colour). In text, `blocked` is "needs you" (alerts, the machine summary).
