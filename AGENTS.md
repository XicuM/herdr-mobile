# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A phone companion for [Herdr](https://herdr.dev) (terminals and coding agents): a Flutter app, at the repo root (Android only; no `ios/` dir, and `linux/` is only the stock desktop runner), terminal-first on `xterm` 4.0.0, vendored in `third_party/xterm` for its fixes: its input client (`custom_text_edit.dart`) diffs each value from the input method against the last instead of resetting it after every insert, which sent text twice when it typed faster than the reset round trip (Voxtype, Gboard voice typing); wheel buttons report as SGR 64/65 (`mouse/button.dart`), at the pointer's local cell (`ui/scroll_handler.dart`); and `CSI > … m`/`CSI ? … m` (Claude Code's modifyOtherKeys) aren't taken for SGR, which underlined everything (`escape/parser.dart`). It talks to [herdr-core](https://github.com/herdrdev/herdr-core) (`hc`), the runtime under the Herdr desktop app, over SSH (`dartssh2`): on each computer it runs `herdr-core connect` (herdr-core's own line for dialing itself, `HcLink._line`) and speaks herdr-core's framed JSON-RPC protocol, documented in that repo's `schema/README.md` (`hc schema` prints the methods). Spaces and tabs are the [Herdr app](https://github.com/herdrdev/herdr-app)'s, kept in herdr-core as its `herdr-app` document. The version for herdr-bridge and Herdr TUI is the `bridge` branch (tag `bridge-final`).

Security: the app logs in with an ed25519 key it makes on first use (`PhoneKey`, pref `ssh_key`, OpenSSH PEM), shown with Copy on every machine's page for `~/.ssh/authorized_keys`; dartssh2 tries `none` after the key, which Tailscale SSH accepts. Host keys are trusted on first use (`_trust`, pref `ssh_host_keys`, `target=fingerprint`) and a changed one fails the connection until it's forgotten on the machine's page (`forgetHostKey`). The APK keeps no Android backups (`allowBackup=false`).

## Commands

Mobile (run from the repo root):
```bash
flutter pub get
flutter run
flutter test                                  # widget_test.dart: models, client, screens; hc_live_test.dart: this computer's herdr-core, if any
flutter test test/widget_test.dart --plain-name "SessionSnapshot parses correctly from JSON"
flutter analyze                               # flutter_lints via analysis_options.yaml
flutter build apk --release
```
CI (`.github/workflows/build-apk.yml`) runs on every push to main, on `v*` tags and by hand: `flutter build apk --release` on Flutter 3.24.x / JDK 17. It also builds the Linux desktop app on both runners (Flutter 3.47.6 cloned from git, since there's no arm SDK archive; `linux/`'s runner needs a newer Flutter than the APK's 3.24) as `herdr-mobile-linux-{x86_64,aarch64}.tar.gz`. On a tag it attaches the APK and those tarballs to the GitHub release. No tests run. Keep Flutter/Gradle/AGP versions compatible with 3.24.x (`dependency_overrides` lets dartssh2, which asks for meta ^1.16 but uses nothing past 1.15, resolve against 3.24's pinned meta) (a newer local Flutter flags `ReorderableListView.onReorder` as deprecated; its replacement isn't in 3.24). Recent commits were spent fixing CI build breakage.

## Architecture

- `models/session.dart` is what the screens show, built in `HerdrClientService._rebuild` from herdr-core's terminal records and the Herdr app's layout: each space a `WorkspaceModel` (named as the app names it: its name, else after where its first terminal is, `~` at home), each tab a `TabModel`, each live terminal in a tab's blocks a `PaneModel` whose id is its address (`t7`), and each terminal whose program reports its status (OSC 7501, `status: {app, state}`) an `AgentModel` named by its app (`claude-code` → `claude`). Agents in no tab (sub-agents, `hc run`) are panes of none. `error` shows as needing you; `turn` (it rises when a turn ends) is the completion count, and `status_ms` (or when the app heard of a change) is when it changed.
- herdr-core facts the app relies on: `events.subscribe` answers with every terminal, then streams `event`s (`created`, `status`, `turn`, `title`, `labels`, `finished`, `removed`, `doc`…) and `missed` with a fresh list; terminals on machines that core added come in the same stream as `name/t7`. In framed mode every frame is `[channel u32 LE][kind u8][len u32 LE][payload]` (DATA 0, CREDIT 1, CLOSE 2, RESIZE 3); channel 0 is JSON-RPC, the events' channel carries JSON lines, and each stream wants CREDIT for what was consumed. A stream's first frames can arrive with the reply that opens it, so `HcLink` holds them until someone listens.

**Mobile** (`lib/`):
- State lives in `HerdrClientService` (a `ChangeNotifier` created in `main.dart` and passed down through constructors).
- A machine is an SSH target (`user@host[:port]`) the phone dials, or `<target>/m/<name>`, a machine that one's herdr-core added (`hc machine add`; `HerdrClientService.parentOf`). When a target connects, `_discover` reads its `machine.list` and puts those right after it, named as there, and forgets those it no longer lists (also every 10 s on screen); their terminals and layout come through the root's link (`_route`: the root's `HcLink` and the `name/` address prefix; `doc.get`/`machine.exec` take `on`). They can be renamed (`machine.rename`), given another target (removed and added again) and removed (`machine.rm`) there. `errorOf(m)` is why a machine can't be shown: while disconnected, why its last connection failed, in words to act on (`_words`: the key not authorized, a changed host key, herdr-core not installed, a name that doesn't resolve, a timeout); for a reached machine, its line's state from `machine.list`. It shows in the machines' panel and in place of the terminal, and goes to `debugPrint` too.
- `HerdrClientService` keeps one `HcLink` per saved target (`_Conn`: link, retry timer, terminals by local address, layout, last snapshot, selected pane), so several machines are connected at once; dartssh2 keeps it alive every 20 s. It subscribes to events (`_onNotification` applies each to the terminals, a `doc` event for `herdr-app` refetches the layout, `missed` replaces them) and rebuilds that machine's snapshot on every change; a dropped link retries after 3 s, doubling with each failure in a row up to ~3 min (reset by connecting, and on resume), so an unreachable machine doesn't keep the phone awake. `_sync` (run from `notifyListeners`, after `start()`) dials every target not in `_off`, the set the user disconnected (pref `hc_machines_off`); `connect(m)`/`disconnect(m)` toggle one machine. The *active* machine (pref `hc_active`) is only the one on screen: `snapshot`, `selectedPaneId` and the requests are its; `switchMachine` shows another without touching the rest. Saved machines are in `hc_machines`, names in `hc_machine_names` (`machine=name`); the bridge's `herdr_*` prefs are left behind. The machines' panel (the home screen's `endDrawer`, `MachineList` in `machines.dart`, opened by the computer icon on the top bar's right, green while one is connected) lists each with a green dot while connected or a warning on error (the error is in its page) and a switch; the + by its title adds a target, or a machine through one's herdr-core, and tapping one opens its page (`showMachinePage`, a full-screen dialog route: a status card with the whole error and its switch, then Connection (its SSH target, this phone's key with Copy, and Forget its host key when that's why it fails, or for a reached machine its target there) and Display (its name), the machines its core reaches, and Remove); held and lifted (or right-clicked) it moves up or down, held and dragged it moves anywhere (`moveMachine`, the app's own order). Spaces and tabs change through `_app`, which runs `herdr-app do <command> <json>` on the target through `machine.exec` (the Herdr window there shows the machines its core reaches too); exit 2 (`no Herdr window`) becomes "open Herdr on … to change its spaces". Other calls go through `_core`. Failures go to the `onError` callback, which `HerdrMobileApp` shows as a SnackBar on any screen.
- `PtyChannel` attaches the selected terminal (`terminal.attach`, 2000 lines of history, `resumed` after a drop) on its machine's link and writes the stream into the single xterm `Terminal`: a first paint that resets the modes and repaints screen and history (the channel clears xterm's own scrollback in front of it), then the program's raw output, with CREDIT for each frame. Keys go back as DATA and size as RESIZE; attaching makes the phone the terminal's active viewer, so it takes the phone's size until the desktop types, resizes or gains focus. xterm does the rest itself: a one-finger drag scrolls its scrollback (`_termScroll`, which shows a centred ↓ back to live while above the bottom), a full-screen program that takes the mouse gets wheel ticks, and a tap on the terminal (or a left click) is a click for the program through `Terminal.mouseInput`, dropped unless it asked for the mouse. A finger's tap is only that click, never the control keys nor the soft keyboard: the keys come only from their button, and the keyboard only from the keyboard button beside them. The keyboard never opens on touch (`_gateKeyboard` holds off xterm's own tap-down by `canRequestFocus` on its focus node, which only the keyboard button puts back), so a tap, a long-press to select or a scroll never shrinks the terminal; on Android the terminal doesn't autofocus, which would open it with every agent. A tap that clears a selection does only that, and the word xterm selects on a double-tap is cleared. While text is selected the output holds still (`PtyChannel.hold`), and it has a text field's two handles to adjust it (`_handleAt`/`_dragHandle`); input, scrolling or another pane let go of it. Ctrl+C copies that selection, as VS Code's does. Omarchy's Super+C reaches the pane as a Ctrl+C whose Control key event the desktop synthesized (`KeyEvent.synthesized`, since no Control key was pressed), and that is what keeps a copy gesture from interrupting the pane: with nothing selected it does nothing, while a real Ctrl+C, with its own Control key, stays xterm's interrupt (`_onTermKeyEvent`). Android 13+ confirms copies itself, so "Copied" shows only below it (`systemShowsCopies`, from the MethodChannel's `sdk`). Two fingers pinch-zoom. When herdr-core ends the stream (the program exited) its reason shows on the dimmed screen. `TerminalScreen` rebuilds the channel whenever `selectedPaneId` or the machine changes, and drops it while the app is in the background.
- **Background alerts** (Android side in `android/.../HerdrApp.kt`): `HerdrApp` (the `Application`) owns the Flutter engine, so Dart, and with it `HerdrClientService`, outlives `MainActivity`. While alerts are on (pref `background_alerts`), Dart drives `StatusService`, a foreground service whose ongoing notification shows the connection state, over the `herdr/android` MethodChannel (`status`, `alert`, `cancel`, `askPermissions`; native calls back `open` when an alert is tapped, and `disconnect` from the notification's Disconnect action, which turns every machine off). The `HerdrClientService.notifyListeners` override pushes the status on every change. `_alertChanges` diffs consecutive snapshots: a pane entering `blocked` raises "Claude needs you", and an agent's `turn` rising past the highest seen for that terminal (`_Conn.completions`) raises "Claude finished"; the text is the agent's summary, the header its place and machine, and its logo the large icon, the only one a collapsed notification shows. The ongoing notification's title is the most urgent count across machines ("2 agents need you"), its text a line per machine. There are no Flutter plugins for this; the Kotlin is plain platform APIs.
- All input goes over the terminal's stream. Terminal keystrokes and the control keys go through `TerminalScreen._send`, which applies an armed CTRL once; special keys use `Terminal.keyInput` so they follow cursor-key mode. There are two places to type: the message box, or the terminal itself with the control keys (`KeyboardAccessoryBar`, a row that scrolls sideways once its keys would be narrower than 48dp) in the box's place (pref `show_keys`, default off). The control keys' button, on the left of the box, brings the keys without the keyboard. On the right, the box's send button; beside the keys, the message box button on the left goes back to the box and the keyboard button on the right shows or hides the keyboard; a keyboard that is up stays up across the swap. The history button inside the box, on its left, opens sent messages and recent slash commands; the image button inside the box, on its right, picks a picture, puts it beside the terminal on its machine (`terminal.put`) and puts its `@`-reference in the box to review and send. The agent's usage (quota %) is on the top bar, left of the machine chip: the herdr-usage mod's numbers (`herdr-usage.v1` in the Herdr app's `~/.config/herdr-app/shared.json` on the target, read with `file.read` on connect and every minute on screen, `_fetchUsage`). The message box (`_sendMessage`) sends its text as one bracketed paste (when the program has enabled it) plus Enter; an empty box sends just Enter. Each pane keeps its own unsent draft (`_drafts`, in memory and static so it outlives the screen, by `machine/pane`); sent messages are kept, for all panes alike, in pref `message_history` and offered by that history button; a history entry goes in the box to edit, while a recent slash command sends straight away (not kept in history). On Android the volume keys, while the terminal screen is on top, change the font size, send ↑/↓, or are left to the system (`VolumeKeys`, pref `volume_keys`, set in Settings; `_onHardwareKey`); Ctrl + and Ctrl - (and Ctrl 0 to reset) zoom the terminal font on Linux/desktop.
- It is laid out like WhatsApp: a list of agents leading into each one's terminal, like chats. The home screen (`AgentsHomeScreen`, `agents_home_screen.dart`) lists every agent on every connected machine as a plain M3 list with faint full-width hairlines between rows, most urgent first and then most recently changed. Each row, like the terminal's top bar, is titled by the summary the agent's terminal title gives (`titleMedium`, bold while it needs you; the agent's name when empty), and under it, smaller, where it is: `SessionSnapshot.placeOf` (the workspace's name, then `(tab_name)` when the workspace has several tabs), then the machine (with more than one), separated by ` · `. It has the agent's logo (`AgentAvatar`, logos in `assets/logos/`) and on the right when it last changed status, a muted icon and its status text/dot. That time is herdr-core's `status_ms`, or when the app heard of a change since (`changedAt`). With no machine connected the search bar's hint says "Connecting…". Tapping an agent switches machine and pushes `TerminalScreen`. There is no FAB: agents start on the computer, and in the workspaces drawer each machine's name has a + that makes a new space there. Swiping right reveals Mute/Unmute, left reveals Close (a slide-and-press action drawer; pressing the revealed button executes the action; tapping the tile or scrolling closes it; undoable): `closePane` closes its pane in the Herdr app (`pane.close`), or ends a terminal in no tab (`terminal.kill`). Long-pressing one, or tapping its avatar, selects it as in Gmail: taps then select more, back clears, and the top bar's actions select all, mute (or unmute, when all are) and close the selection. `closePane` takes the agent's machine, so closing never switches the screen. The top bar has ☰ on its left, a search pill in the middle (a stadium `Container` with the search icon in a 48dp slot on its left, as wide a slot on its right for the clear button, and a `TextField` centred between; M3's `SearchBar` can't centre its text), and on its right the machines' icon (green while one is connected). ☰ opens the drawer and tapping the machines icon opens the machines' panel (only they do, `drawerEnableOpenDragGesture`/`endDrawerEnableOpenDragGesture: false`, since an edge swipe would fight the rows' swipe and Android's back). The drawer (`WorkspacesDrawer`, shared with the terminal's) holds Settings at its foot and the workspaces (`WorkspaceList` in `workspaces.dart`, modelled on Herdr's sidebar: each connected machine's spaces under its name (always shown, with its +; one off, connecting or failing is left out); tap one to open its terminal, hold it and lift (or right-click) for its menu (`showWorkspaceContextMenu`: Rename and Close), hold and drag to reorder it (`space.move`, the app's own order so the desktop follows); each acts on its row's machine first, since requests go to the active one; opening a terminal from it closes it first). There is no bottom bar, so no unread badge: the agents that need you are on top and in bold. Tapping the search bar (`_query` non-null) swaps ☰ for back and replaces the body with sectioned results, as WhatsApp's: Agents (the list's own rows, swipes and selection included), Workspaces, Tabs (how a plain shell is found by name) and Machines (`MachineList(only:)`). Every word must be somewhere in what a result shows or is known by: names, its agents, its machine, its status's label or `machineStatus`. Tapping a result switches to its machine and opens its terminal (a machine opens its page); search stays open behind it, and back closes it after any selection. The welcome and "What's new" dialog shows from the home screen.
- On a landscape tablet (`_isWide`: at least 840dp wide and 600dp on its short side, so not a phone in landscape) the home screen is M3's list-detail layout: the list and its top bar in a 360dp pane on the left, and the selected pane's terminal beside it (`TerminalScreen(embedded: true)`: no back button, and it never pops itself; the home screen shows "No agent open" instead once its pane or machine is gone). Tapping an agent shows it there instead of pushing, and its row is marked. Turning narrow pushes the shown terminal, and turning wide pops a pushed one back beside the list (`_onWidthChange`).
- `TerminalScreen` is the chat: back returns to the list, and if its machine is switched off or removed it pops itself, with whatever is open over it. Its top bar shows the workspace's name. On the right, the agent's usage (its logo and the quota left in done's green, from 75% used the draft peach, from 90% needs-you's red, and grey with nothing recorded; none for a pane with no agent), which opens its usage sheet, and an `ActionChip` with the machine's name and its status (`machineStatusIcon`, drawn the same everywhere: green dot connected, hollow dot connecting, warning on error, none when off), which opens its page (`showMachinePage`: its status with the whole error, its switch, then Connection, Display, Remove); the header names the workspace and opens the workspaces panel when tapped: the home screen's beside the list, else the terminal's own over it, where picking one switches the pane in place. Its actions are in that panel. Alt+W closes the pane and goes back. Under the top bar, in `AppBar.bottom`, the workspace's tabs, like Vivaldi's: a strip of equal 168dp tabs that scrolls when they overflow, kept scrolled to the current one; it's how plain shells are reached, since the list shows only agents. Each tab shows its agent's avatar with an online status ring and its truncated summary (`_tabSummary`); the current tab is rounded on top and takes the terminal's background, joined to it, against the bar's `surfaceContainer`; a fixed new-tab button at the end; a tab held and lifted (or right-clicked) has a menu to open it, move it left or right or close it; hold and drag a tab to move it, the others sliding aside to show where it lands (a horizontal `ReorderableListView`; `tab.move`). It is the one hand-drawn control besides the terminal, since M3 has no browser tab. The UI is Material 3: the theme in `main.dart` is `ColorScheme.fromSeed` in light and dark, from the accent colour and light/dark/system mode picked in Settings (`HerdrClientService.seed`/`brightness`, prefs `theme_seed`/`theme_mode`); with no accent picked on Android 12+ it is the device's own Material You scheme, built from its tonal palettes (`HerdrApp.kt`'s `systemPalette` over the MethodChannel, read on every resume into `systemPalette`; `_fromPalette`), not a seed regenerated from one shade, so a white or grey system accent stays neutral; `systemColor` over the MethodChannel only gives the Settings swatch; else sky. It isn't read through the `dynamic_color` plugin, whose Gradle script doesn't build with CI's Kotlin/AGP, widgets use scheme roles, the type scale and stock M3 components; only the terminal uses the Meslo font, and only `AgentStatus.color` (with which the usage chip also warns) and the connected green are hardcoded.
- Closing a tab or workspace is never asked about but always undoable: a tab (menu, Alt+W) or a workspace hides at once and a SnackBar ("Tab closed", "Workspace closed") offers Undo just above the message bar (or at the bottom), as Gmail's does, in M3's inverse surface colours; the request goes once it ends without Undo, or another replaces it (`closeWithUndo` in `workspaces.dart`, over `HerdrClientService.closeUnlessUndone`, which keeps herdr's snapshot as `_Conn.raw` and shows it less `_hidden`; a hidden selected pane moves on as when herdr closes it). An agent closed from the list (its Close, the menu's, or the selection's) hides at once too and its SnackBar ("Agent closed", or "Agents closed") offers the same Undo, at the bottom of the screen. Removing a machine is the one thing asked about first.
- `lib/changelog.dart` (newest first) drives the first-launch welcome and the one-time "What's new" dialog, keyed by the `last_seen_changelog` pref. When releasing, bump the version in `pubspec.yaml` (Gradle reads it), then add a changelog entry.
- Agent statuses are `working | blocked | done | idle | unknown` (`AgentStatus`, an enum with each one's colour). In text, `blocked` is "needs you" (alerts, the machine summary).
